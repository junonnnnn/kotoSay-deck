# Competitor notes (slide 9: comparison matrix)

Checked on 12 Oct 2026 against public sources, so the matrix holds up if judges ask.
Update this file and `src/slides/09-competition.html` together.

The three needs (from the brainstorm doc): **their own sign language**,
**available anytime**, **answered in sign**.

| Option | Own sign language | Anytime | Answered in sign | Notes |
| --- | --- | --- | --- | --- |
| Human interpreters | Yes | **No.** Needs advance booking | Yes | As stated in the brainstorm doc. |
| SoftBank SureTalk | Yes, reads JSL by camera | **No.** Tied to a service counter | **No.** Replies shown as text | Signs → text, and the hearing person's speech → text. Japanese → sign output is only a wish from pilot staff, not a feature. Pilots so far: Tokyo 2025 Deaflympics, Narashino City welfare counter. Pricing isn't published, so the slide says "service counter", not "paid counter". |
| UD Talk | **No.** Deaf user must type | Yes, phone app | **No.** Text captions only | Speech recognition + translation shown as text. |
| Google SL2T | **Partly.** ASL → English only, so far | Yes, on Pixel phones | **No.** Cannot sign back | Launched 12 Aug 2026 in Gboard and Live Transcribe, Pixel 11 first. Trained on 50+ sign languages but ships ASL → English only. Sign generation is listed as future work. |
| **kotoSay** | Yes, JSL + MSL | Yes, on demand | Yes, 3D avatar | |

> The brainstorm doc says each rival misses exactly *one* need. The sources show
> SureTalk, UD Talk and SL2T each miss *two* (they all reply in text), so the slide
> says **"every alternative misses at least one need"**. That claim is accurate, and
> it's stronger.
